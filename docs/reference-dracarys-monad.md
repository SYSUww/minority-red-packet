# Dracarys Monad 邀请与支付参考

调研对象：[`Chandukasireddy/Dracarys_Monad`](https://github.com/Chandukasireddy/Dracarys_Monad/tree/b1c338e06b071c7c25377c39f954982cb3312bdc)，固定在提交 `b1c338e06b071c7c25377c39f954982cb3312bdc`。

目标是吸收产品流程和工程分层，不复制其合约与身份实现。GitHub 未识别到仓库顶层开源许可证，因此也不应直接搬运源码。

## 值得借鉴

- 邀请闭环：邀请码、深链、二维码、系统分享和站内定向邀请同时存在。
- 付款前确认：先展示挑战内容和应付金额，再请求钱包权限。
- 钱包 adapter：网络切换、余额检查、Gas 估算、`eth_call` 模拟、发送和 receipt 等待集中在一层。
- 社交与资金分层：后端保存用户、成员和邀请状态，合约只处理资金事实。
- 移动端入口：普通手机浏览器中提供 MetaMask App deep link。
- 可验收界面：Playwright 覆盖创建、校验和二维码出现。

## 本次落地

- 邀请页在连接钱包前先读取链上房间，展示押金、已加入人数和当前阶段。
- 统一交易出口增加余额、Gas 估算和合约模拟，预检失败时不请求钱包签名。
- 增加 MetaMask 手机 App 打开入口。
- 生产环境的 `NEXT_PUBLIC_CONTRACT_ADDRESS` 优先级高于邀请 URL，链接不能替换固定付款合约。
- 生产邀请链接在已配置固定合约时只携带房间号；`contract` query 只作为未配置固定合约的开发降级路径。

## 不能照搬

- 后端直接信任 `user_id`、`inviter_id`、钱包地址和审批人，缺少会话与签名 nonce 验证。
- `burnSlacker` 没有记录“某人某天已结算”，可重复执行并抽干资金池。
- 惩罚分配采用循环 push payment，任一收款方 revert 都可阻断整个结算。
- 多赢家完成奖励会按递减资金池重新计算，后领取者金额变小且可能残留锁死资金。
- 链上成功后再写后端，却没有以 tx hash 做幂等和失败恢复，会导致资金事实与社交数据分叉。
- 邀请码只有 6 位十六进制、无过期和次数限制，不适合直接用作资金授权。

## 后续边界

当产品需要“站内好友邀请”时，再引入带鉴权、唯一约束、过期时间和 tx hash 幂等的服务端邀请表。如果邀请需要返佣，它就是资金语义，必须同步修改合约、ABI、gateway 和合约测试，不能只增加前端参数。
